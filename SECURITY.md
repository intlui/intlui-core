# Security reporting

Do not post credentials, customer data or exploitable vulnerability details in a
public issue. Once the GitHub repository is public, use its Security tab to report
privately if private vulnerability reporting is enabled. If it is unavailable,
open an issue requesting a private contact without including sensitive details.
The repository owner should enable private vulnerability reporting at publication.

This is an initial development preview; no supported stable release or response
time guarantee is announced. Model output and incoming wire data are untrusted.
Custom profile adapters are trusted application modules and must validate their
grammar, data and runtime boundaries. Never execute model-selected modules.
